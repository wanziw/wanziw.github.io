[论文阅读]单细胞基础模型汇总

发表于2026-09-07|更新于2026-09-07|论文阅读
|字数总计:3.2k|阅读时长:10分钟|阅读量:

scBERT

将 scRNA-seq 数据使用语言模型建模，一个首要问题就是，如何将这样的表格数据变成序列并合理地代入 BERT 架构进行 Tokenization、输入数据 Embedding、输出数据的处理和应用。scRNA-seq与 DNA/RNA 序列、自然语言序列的区别带来了必须要解决的问题：

  • 单细胞基因表达数据是一个 细胞 x 基因 的矩阵，如果我们把每个细胞的基因表达作为一个序列，表达值是与它所代表的基因相绑定的；而一个句子由 单词/Token 构成，它的意义是与其所处的位置绑定的 (所以才会有 Postitional Embedding)。两者的不同决定了 Embedding 的设计要有所不同。
  • 基因表达值是连续变量，而 碱基序列/单词 是离散变量，Tokenization 将一个个词汇变成序号/数字，基因表达值该如何处理？
  • 每个细胞都有上万的基因表达，这意味着序列长度远超之前 BERT 模型中 512 的序列长度。而由此带来的，是模型训练、推理过程中内存消耗二次方级上升，该如何解决？
  • scRNA-seq 由于测序技术所带来的，是很大比例的缺失值 (dropouts)，和不同数据间的批次效应，这些数据独特的问题，训练中应该如何处理？

因此，scBERT 在 BERT 的基础上，针对 scRNA-seq 数据在模型设计上做了不少的改动，包括 Tokenization 方法、Embedding 层改动、替换 Transformer 层为 Performer 层等

  • Tokenization
    • 采用了传统的术语频率分析方法，通过分箱 (binning) 将连续的表达变量离散化
    • scRNA-seq 数据经过 log1p 转化，通过将浮点数转换成整数数据类型，实现了表达值离散化处理。经过处理的表达值，在研究中一共有 7 个分箱值 (1 - 7)，加上 0 代表的缺失值，和 8 代表的 [MASK] 符号，scBERT 一共有 9 个 Token/词汇
    • 当然7个分箱值可能会让任务变得简单，损失率很多的信息
    • scBERT 将 scRNA-seq 转化为的基因表达序列，永远是固定的 16k 基因。不同的数据来源有着不同的批次效应和缺失值，强行要求输入为固定的 16k 基因毫无疑问会引入更多的噪声。当然，scBERT 的出发点是每一个基因对于细胞活动和类型都是重要的，因此他们选择了涵盖尽可能多的基因。但单细胞数据的质量是否真的支持这样做，他们的预训练数据大小 (1.13M 细胞) 是否足够学习到噪声和真实信号的区别，研究还未能给出明确的答案。在后续 scGPT、Geneformer 论文中还会有不同的基因表达序列转换方法
  • 模型架构
    • batch：一次给模型多少个细胞
    • seq：16906+1，基因的总数+末尾的0。同时输入的gene永远是一致的顺序
    • V=9。scBERT 的词汇量 (7个分箱值 + 0 + [MASK])
    • D_h =200。Hidden dimension，每个分箱值都会被转换为长度为D_h 的向量表示
  • input
    • 输入包括Token Embedding (输入的词汇序号映射成为隐藏维度向量) 和 Positional Embedding (给每个 token 向量添加可训练的位置信息)
    • 但是，位置对于基因表达量序列并没有什么意义，更有意义的是每个位置都是什么基因 (例如基因名字)。如果能将这个信息告知模型，模型就可以在注意力机制中学习基因之间的相互作用关系。因此，scBERT 将 Positional Embedding 替换成了 Gene Embedding，将基因名字转换为一个向量。
  • 为什么单细胞基础模型。跟nlp、dna/rna序列大模型不一样
    • 前者输入顺序固定，后者是随机的。
    • 本质上大模型不关心顺序，只关系token和token之间的关联性。在序列模型中，关心position，代表了上下单词间的语义联系，所以专门有一个position embedding。
    • 而单细胞模型里，我们不关心顺序，所以有一个Gene Embedding，来代表Gene identity就行。所以不依赖 NLP 那种“顺序语义”
    • 此外，两者的Token Embedding倒是一样，一个是word embedding，一个是expression embedding
  • 下游任务：细胞类型注释

Geneformer

总的来说，Geneformer 用一种独特又巧妙的策略实现了将 scRNA-seq 这样的【表格数据】变成自然语言一样的【序列数据】，并在此基础上实现了多个下游任务微调的设计，还提出了 In Silico Perturbation 方法。

  • 之前的scBERT一直要输入1.6w的gene，单细胞数据里全是噪声
  • 于是Geneformer 设计了 Rank Value Encoding 方法

既然单细胞数据稀疏性如此的高，Geneformer 干脆就把这些不包含有效信息的基因都丢掉。随之而来的一个问题是，如果把每个细胞的基因表达作为一个序列，那这些序列所包含的基因就不一样了，而我们序列的输入值是表达量，并不包含基因名字/ID 的信息，这些乱七八糟的表达值无法用来进行预训练，也没有办法设计训练任务。

但在 Geneformer 看来，我们何必一定要限制模型用基因表达量作为输入呢？在 Geneformer 的 Rank Value Encoding 中，基因的名字被用作组成每一个细胞的序列，而基因名字的排列，则按照一定方式预处理后的表达值由高到低进行排序。这样一来，表达值的意义就包含在了基因的排列之中。这样的序列，位置也是有意义的 (表达量高低)，且长短不受限制，更加接近自然语言的建模方式。

对于每个细胞，只输入2048，不足的用，于是一个表格一样的基因表达矩阵，就被转换成了自然语言序列 Tokenization 之后的一串长度不等的数字

  • 图里面
    • 每个gene先是经过按细胞做 normalization
      • 解决不同细胞测序深度不同的问题
    • 然后按 gene 做 normalization
      • 对每一个 gene，在所有细胞里计算它的 non-zero median，作为这个 gene 自己的“基准水平”
    • 这样子可以优先考虑区分细胞状态的基因，弱化一些管家gene，强化一些特殊功能的gene

计算 27.4M 细胞数据的 non-zero median 值在计算资源的消耗上并不是个简单的事情。因此，在数据格式上，作者选择了 HDF5 的 .loom 文件进行存储和读取。在计算过程中，作者使用 loompy 扫描 .loom 数据块，以内存高效的方式汇总每个基因的转录本 counts 分布，并在t-digest 数据结构中更新基因的标准化 counts 分布 (该数据结构是为 online accumulation of rank-based statistics 而开发的，如果有机会，会在代码解读文章中讲解)

  • 模型上input
    • 采用了Token Embedding（不是表达量，只有Gene ID对应的向量） + Position Embedding 的设计
  • output
    • Cell-level Classifier，对应 BERT 的 Sentence-level Classifier。可以用来进行细胞/序列水平的分类任务，例如预测细胞类型。在 BERT 中，每个序列的最前面加了 ，用来学习整个句子的向量表示。但是，Geneformer 并没有使用 ，而是直接用了第一个基因经过 Transformer 层后的表示向量进行了上述一系列操作，作者表示这是有意而为之，他们认为第一个基因在 Fine-Tune 过程中可以既承担基因的信息，又承担序列表示信息。(详情见: https://huggingface.co/ctheodoris/Geneformer/discussions/227)
    • Gene-level Classifier，对应 BERT 的 Token-level Classifier。给每个 gene token 输出一个分类分数。
  • 下游任务
    • 提出了In Silico Analysis

RegFormer

传统的模型geneformer、scfoundation、scBERT，都是把scRNA-seq当作序列在处理，但是scRNA-seq 中的基因本身并不存在天然的线性顺序；与此同时，真实生物系统却存在明确的 转录因子 → 靶基因 的调控层级。

大部分的基础模型都是把GRN信息当作先验证知识融进模型里。

最开始用TF-motif-TG，做initial GRN，每个TF取前20个TG

对每个gene做Node2Vec，graph embeding。

同时要求是有向无环图，去除了循环的边。

topological sorting这个方法可以实现：上游 regulator 排在下游 target 前面。

  • Mamba
    • 对 scan order 敏感
      • Mamba 原论文把它描述成沿 sequence length 做 selective propagation/forgetting，而且具有线性 sequence scaling
      • 而自注意力机制本身没有这个位置的观察，大语言模型需要加入position
      • 所以GRN排序非常适配Mamba，直接利用state来传递信息
    • 可以解决长序列的问题，相比transformer

Transformer：能学远距离关系，但是长到 10k、20k、更多以后越来越贵。

Mamba：也能学长距离关系，但更适合把上下文做得很长。

scGPT 最大 sequence length：1200

Geneformer：2048

而RegFormer可以做到10k

整个模型的原理简单来说就是，把原本的GRN，最初始的GRN，用motif做出来的，改变输入的genes序列的顺序，从而直接让模型初始就能理解到基因存在 regulatory hierarchy，直接把这个 hierarchy 直接塞进模型。

  • 设计loss
    • 权重MVP(0.1)、GEPC(0.5)、TOPO(1)
    • 一次 forward，得到三个 loss，然后把三个 loss 加权起来，一起反向传播。

add/concat的区别

【特征融合方式】

  1. add融合：这种方式就像是调料包混合，当特征之间独立且互补时，add操作能够有效地整合信息，减少参数和计算量。但就像混合后的调料包无法再分开一样，add融合也会带来一定的信息损失。
  2. concat融合：与add不同，concat更像是把各种食材摆满一桌。它保留了原始特征向量的所有信息，是一种无损的融合方式。但就像处理一桌丰富的食材需要更多时间和精力一样，concat融合也会增加参数和计算量。
  3. 【选择融合方式的考量】
    • 任务需求：如果任务要求保留尽可能多的原始信息，或者输入特征之间具有较强的相关性，那么concat可能是更好的选择。
    • 计算资源：如果计算资源有限，或者追求更高效的模型，那么add融合可能更适合，因为它能够减少参数和计算量。

问题和质疑

  • 这个模型有一个问题就是依赖原本的一个GRN，但是原本的GRN本身就是不一定准确的

  • “gene identity + expression value”有点抽象。说是类似token embedding + positional embedding，为什么是add，而不是concat，这个很重要

    • 对于我们的项目来说 最好还是用concat

  • 没懂这个cell embedding，所有的几万个gene embedding每个维度的值做平均

  • TOPO 更像“结构约束”，而不是“结构发现”

    • 模型被要求把已有 GRN 先验编码到自己的参数/表示里。更像是一种辅助结构loss
    • topo这一块要好好研究一下他的逻辑到底对不对，这个gene序列的顺序说实话，有很多不一定对的，而且大部分可能都是没有意义的，就少部分才有意义，比如a调控b和c，但是排序是a那不是把b-c这个本身不存在的关系也当作有顺序关系了吗，但是loss的权重又很大。
    • 如果不对的话，后面自己训练模型，这一个可以不需要或者降低权重
    • 如果没有topo，这种开头GRN控制gene顺序的创新会不会其实就没用
    • 某些程度上更像时间序列or一维图像，但是又实用了next token prediction的技术
    • 可以从视觉模型中xuexi：“视觉模型如何解决 flatten 后结构丢失的问题”，弥补这里的GRN
      • fixed ordering + long-range state propagation：Mamba / SSM / scan / long sequence
      • 什么一个有结构的 2D object 不能随便 flatten 成 1D？：Vision Mamba
      • sequence model + graph connectivity 怎么同时存在？：Graph + sequence hybrid

bulkformer

一般的单细胞基础模型只取比如top2000的gene，单细胞是合理的，因为数据稀疏

这恰恰是 BulkFormer 对这些 scFM 的批评：bulk 的 transcriptome 更 dense，所以应该利用完整表达谱；BulkFormer因此专门设计了适配 bulk 的连续表达编码和 full-transcriptome modeling。

用的基本是别人整理好的rna-seq

  • 没有做 metadata integration，没有使用metadata信息
